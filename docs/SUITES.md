# CRT suite index — every `.robot` file, its purpose, and its complete step list

Generated 2026-09-18 from the suites as committed in this repo (`tests/`), cross-referenced against
`docs/recorder/patterns/library.json`, `tools/recorder/pattern_library.py`, the locator doctrine in the
orchestrator repo's `CLAUDE.md`, `docs/recorder/review/slockard-zoo-nightmare-inputs/review.json`, and
`docs/recorder/evidence/crt-live-testing-recorder-network-2026-09-18.md` (parts 6–9). Credential
variables (`${client_id...}`, `${username...}`, `${private_key...}`) live in CRT's own Variables
section, never in this repo — never resolved or searched for here.

## How to read this file

Each suite gets: **Purpose** (from its own `Documentation`), **Org**, **Prerequisites**, then a
**step checklist**. Every checklist row is one keyword line as it appears in the suite, in order,
with two extra columns:

- **Pattern** — the recipe it instantiates, named by its `id` in `docs/recorder/patterns/library.json`
  (see `docs/PATTERNS.md`), or one of: `auth` (login), `navigation` (URL-first GoTo / page-object
  keyword), `QForce native` (a stock QForce/QWeb keyword with no recipe needed — the control is a
  plain labelled field, button or link), or `policy` (a step that is deliberately never executed live,
  per `save-never-live`).
- **Verification** — `assertion` (the line itself is a Verify*/Is* check), `read-back` (the *next*
  line reads back what this one did — named), `resolution-only` (the line proves the locator resolves;
  nothing asserts its effect), or `none` (no check follows; commonly a commented-out mutating step).

Suites generated by `tools/recorder/pom/export_flow.py` keep their own `# PAGE:` / `# TRANSITION:` /
`# STATE:` markers as sub-headings, reproduced verbatim. Suites generated by
`tools/recorder/review_table.py robot` (the `fsc-*`, `hc-*`, `slockard-*` page reviews and the three
`copado-cicd-pages/0{1,2,3}` files) are built from **buckets**: same-shape controls that took the same
call shape with only the label changing (`tools/recorder/pattern_library.py`, and CLAUDE.md's own
"**Patterns, not rows**" rule, user 2026-09-10). Where a suite has 400+ mechanically-identical rows
this file documents it by bucket — every row number is still named, just grouped — rather than
re-typing 400 near-identical lines.

Dreamforce suites' inline `# SAY:` / `# BRIEF:` / `# WHY THEY CARE:` / `# VOCAB:` / `# UNVERIFIED:`
comments are kept as each step's note, unabridged.
